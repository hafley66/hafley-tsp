# Plan: Universal Expression Components for Polyglot Emitters

## Context

The Rust emitter (`5_emit-rust.tsx`, 907 lines) uses two emission modes:
- **JSX (Alloy)**: struct/enum/trait declarations via `<StructDeclaration>`, `<FunctionDeclaration>`, etc.
- **String concat**: function bodies, SQL, JSON access, sync control flow via `lines.push()`

The goal is to eliminate string concatenation entirely by building universal
expression-level JSX components that render valid syntax in Rust, Go, and TypeScript
depending on a language context. These sit between the existing declaration components
(Layer 0) and domain-specific components (Layer 2).

```
Layer 2: Domain components (future)     <SqlQuery>  <SyncLoop>  <JsonExtract>
Layer 1: Universal expressions (this)   <Let>  <If>  <For>  <Call>  <Await>  <Try>
Layer 0: Declarations (exists)          <StructDeclaration>  <FunctionDeclaration>  <TraitDeclaration>
```

## Prior art in the codebase

### Alloy core primitives (from @alloy-js/core)
- `Block` -- indented `{ }` wrapper, auto-hardline
- `For` -- iterator with joiner/ender/comma/hardline options
- `List` -- static children with configurable separators
- `Declaration` / `Name` / `Scope` -- symbol binding + scoped resolution
- `Show` -- conditional rendering (when/fallback)
- Intrinsic formatting: `<hbr/>`, `<sbr/>`, `<indent>`, `<group>`, `<fill>`
- `Children` type accepts strings, JSX, arrays, functions, refs
- Raw strings pass through the renderer unchanged (escape hatch)

### Existing Rust components (packages/rust/src/components/)
- `0_primitives/`: Generics, Attributes, Serde, Comment, ReferenceTypes
- `1_declarations/`: StructDeclaration, EnumDeclaration, TraitDeclaration, FunctionDeclaration, ImplBlock, VariableDeclaration
- `2_references/`: Reference, UseStatement, ModStatements
- `4_codegen/`: AppendZone, CodegenPair, ReplaceFile, AxumEndpoint, TransportBinding

### Context system
- `createContext<T>(initial, name)` returns Provider + `useContext()` hook
- Used for: `VisibilityContext`, `ImplPathContext`, `ZoneRegistryContext`
- `NamePolicy<T>` handles per-language identifier casing (snake_case, PascalCase, camelCase)

## Architecture: Three new packages/modules

### 1. Language Context (`packages/@shared/lang-context/`)

A context provider that tells components which language to render. Option C design
(dialect registry via context) -- extends the existing NamePolicy pattern.

```typescript
type SupportedLanguage = "rust" | "go" | "typescript";

interface LangContext {
  language: SupportedLanguage;
  syntax: LanguageSyntax;
  declModifiers: DeclModifierProvider;
}

interface LanguageSyntax {
  structKeyword: string;         // "struct" | "type" | "interface"
  functionKeyword: string;       // "fn" | "func" | ""
  visibilityKeyword(pub: boolean): string | null;
  optionOp(inner: string): string;  // "Option<T>" | "*T" | "T | null"
  errorReturnPattern(retType: string): string;
  awaitSyntax: "suffix" | "prefix" | "none";  // .await | await x | goroutines
  trySyntax: "suffix" | "statement" | "none";  // ? | if err != nil | try/catch
  formatCall(template: string, args: string[]): string;
}

interface DeclModifierProvider {
  visibility(pub: boolean | undefined): string;
  mutability(mut: boolean | undefined): string;
}
```

Each language registers a dialect:
- `createRustDialect()` -- `struct`, `fn`, `pub`, `Option<T>`, `.await`, `?`
- `createGoDialect()` -- `type`, `func`, case-based, `*T`, goroutines, `if err`
- `createTSDialect()` -- `interface`, `""`, `export`, `T | null`, `await`, `try`

Usage at top of emitter:
```tsx
<LangContextProvider language="rust">
  <FunctionDeclaration ...>
    <Let name="x" value="42" />
  </FunctionDeclaration>
</LangContextProvider>
```

Components consume via `useLangContext()` hook. Falls back to existing
`VisibilityContext` / `NamePolicy` when not wrapped.

### 2. Statement Components (`packages/@shared/statements/`)

~7 components for universal imperative control flow.

#### Let -- variable binding
```typescript
interface LetProps {
  name: string;
  type?: Children;     // optional annotation
  value?: Children;    // RHS expression
  mutable?: boolean;   // Rust: let mut, Go: ignored, TS: let vs const
}
```
| Lang | Output |
|------|--------|
| Rust | `let [mut] name[: Type] = value;` |
| Go   | `name := value` or `var name Type = value` |
| TS   | `const name[: Type] = value;` |

#### If / ElseIf / Else -- conditionals
```typescript
interface IfProps {
  condition: string | Children;
  children?: Children;  // block body
}
```
| Lang | Output |
|------|--------|
| Rust | `if cond { body }` |
| Go   | `if cond { body }` |
| TS   | `if (cond) { body }` |

ElseIf/Else chain by adjacency in JSX tree.

#### ForIn -- iteration
```typescript
interface ForInProps {
  pattern: string;       // "item", "{ name, age }", "_, item"
  iterable: Children;
  children?: Children;
}
```
| Lang | Output |
|------|--------|
| Rust | `for item in collection { }` |
| Go   | `for _, item := range collection { }` |
| TS   | `for (const item of collection) { }` |

#### Match / Arm -- pattern matching
```typescript
interface MatchProps {
  expr: string | Children;
  children?: Children;  // <Arm> elements
}
interface ArmProps {
  pattern: string;       // "Some(v)", "42", "_", "default"
  guard?: string;        // Rust only: "if v > 0"
  children?: Children;
}
```
| Lang | Output |
|------|--------|
| Rust | `match expr { Pat => { body }, }` |
| Go   | `switch expr { case Pat: body }` |
| TS   | `switch (expr) { case Pat: body; break; }` |

#### Return
```typescript
interface ReturnProps {
  value?: Children;
  values?: Children[];  // Go multi-return
}
```

#### Assign
```typescript
interface AssignProps {
  target: string | Children;
  value: Children;
  operator?: "=" | "+=" | "-=" | ...;
}
```

### 3. Expression Components (`packages/@shared/expressions/`)

~7 components for universal expression-level constructs.

#### Call -- function invocation
```typescript
interface CallProps {
  name: string | Children;
  args?: Children[];
  namespace?: string;  // Rust: `::`, Go/TS: `.`
}
```

#### MethodCall -- method invocation
```typescript
interface MethodCallProps {
  receiver: Children;
  method: string;
  args?: Children[];
  async?: boolean;  // adds .await (Rust) or await prefix (TS)
}
```

#### Await -- async modifier
```typescript
interface AwaitProps { children: Children; }
```
| Lang | Output |
|------|--------|
| Rust | `{children}.await` |
| Go   | `{children}` (no-op) |
| TS   | `await {children}` |

#### Try -- error propagation
```typescript
interface TryProps { children: Children; }
```
| Lang | Output |
|------|--------|
| Rust | `{children}?` |
| Go   | requires statement-level `if err != nil` (separate component) |
| TS   | passthrough (caller wraps in try/catch) |

This is the hardest translation. Rust `?` is expression-level, Go error handling
is fundamentally statement-level. For Go, a `<GoTry>` component emits the
multi-line `if err != nil { return err }` pattern. The universal `<Try>` is
Rust/TS only.

#### Field -- property access
```typescript
interface FieldProps { receiver: Children; field: string; }
```
Renders `receiver.field` in all languages. Name casing handled by NamePolicy.

#### Fmt -- string interpolation
```typescript
interface FmtProps {
  template: string;
  args?: Children[];
}
```
| Lang | Output |
|------|--------|
| Rust | `format!("template", args)` |
| Go   | `fmt.Sprintf("template", args)` |
| TS   | `` `template` `` with `${}` |

#### Chain -- method chaining
```typescript
interface ChainStep {
  kind: "method" | "call";
  name: string;
  args?: Children[];
}
interface ChainProps {
  start: Children;
  steps: ChainStep[];
  endAwait?: boolean;  // .await at end (Rust)
  endTry?: boolean;    // ? at end (Rust)
}
```
Handles patterns like `sqlx::query("...").bind(x).bind(y).execute(conn).await?`

## Where string stays honest

Some content is inherently string-shaped. Wrapping it in components adds
indirection without clarity:

- **SQL query text**: `"INSERT INTO repo (owner, name) VALUES (?, ?)"` -- always a string literal
- **JSON path access**: `item["reviews"]["nodes"]` -- structural string indexing
- **GraphQL field selections**: multi-line query text
- **Serde attributes**: `#[serde(rename_all = "camelCase")]`

These remain as string children inside JSX components. The components handle
the *control flow scaffolding* around these strings, not the strings themselves.

Estimated split: ~60% of current string emit becomes JSX components,
~40% stays as string content passed as children.

## Migration sketch: emitUpsertFn

Current (string, 61 lines):
```typescript
lines.push(`pub async fn ${fnName}(`);
lines.push(`    conn: &mut SqliteConnection,`);
for (const p of params) lines.push(`    ${p},`);
lines.push(`) -> Result<${returnsId ? "i64" : "()"}> {`);
lines.push(`    sqlx::query(`, `        "INSERT INTO ${tableName}...`);
for (const f of upsertFields) lines.push(`    .bind(${paramName})`);
lines.push(`    .execute(conn)`, `    .await?;`, `    Ok(())`);
```

JSX equivalent:
```tsx
<FunctionDeclaration name={fnName} async pub
  params={[{ name: "conn", type: "&mut SqliteConnection" }, ...params]}
  returns={`Result<${returnsId ? "i64" : "()"}>`}>

  <Chain
    start={<Call name="sqlx::query" args={[sqlString]} />}
    steps={upsertFields.map(f => ({ kind: "method", name: "bind", args: [paramExpr(f)] }))}
    endAwait endTry
  />
  {"Ok(())"}
</FunctionDeclaration>
```

The function signature moves from string to JSX (cleaner). The SQL string
stays as a string child. The `.bind().bind().execute().await?` chain becomes
a `<Chain>` component.

## Migration sketch: emitSyncFn structure

```tsx
<FunctionDeclaration name={`sync_${table}`} async pub
  params={[conn, client, ...pathParams]}
  returns="Result<()>">

  {/* Endpoint + poll state */}
  <Let name="endpoint" value={endpointExpr} />
  <Let name="poll" value={<Try><Await><MethodCall receiver="client" method="get_poll_state" args={[...]} /></Await></Try>} />

  {/* Poll interval check */}
  {pollInterval && <If condition="let (Some(interval), Some(ref last_polled)) = ...">
    <If condition="elapsed < interval">
      <Return value="Ok(())" />
    </If>
  </If>}

  {/* Build request */}
  <Let name="req" mutable value={<>{"SyncRequest { ... }"}</>} />
  {freshness === "etag" && <If condition="let Some(ref etag) = poll.etag">
    <Assign target="req.etag" value="Some(etag.clone())" />
  </If>}

  {/* Transport call */}
  <Let name="resp" value={<Try><Await><MethodCall receiver="client" method="rest_call" args={["conn", "&req"]} /></Await></Try>} />
  <If condition="resp.is_not_modified()"><Return value="Ok(())" /></If>

  {/* Item loop */}
  <ForIn pattern="item" iterable="items">
    <Let name="fields" value={<Call name={`extract_${table}`} args={["item"]} />} />
    <Try><Await><Call name={upsertFn} args={upsertArgs} /></Await></Try>

    {/* Nested children */}
    {nestedChildren.map(child => <>
      <If condition={`let Some(children) = item${child.jsonAccess}.as_array()`}>
        <ForIn pattern="child" iterable="children">
          <Let name="child_fields" value={<Call name={`extract_${child.table}`} args={["child"]} />} />
          <Try><Await><Call name={child.upsertFn} args={child.args} /></Await></Try>
        </ForIn>
      </If>
    </>)}
  </ForIn>

  {/* Poll state save */}
  <Try><Await><MethodCall receiver="client" method="set_poll_state" args={["conn", "&endpoint", pollStateExpr]} /></Await></Try>
  {"Ok(())"}
</FunctionDeclaration>
```

## Design decisions

| Decision | Rationale |
|----------|-----------|
| Dialect context (Option C) | Extends existing NamePolicy pattern, O(1) new language cost |
| Separate statements/expressions packages | Different composition rules, different dependency shapes |
| `<Try>` is Rust/TS only | Go error handling is statement-level, needs `<GoTry>` for multi-line pattern |
| String children for SQL/JSON | Inherently string-shaped content, wrapping adds noise |
| `<Chain>` as explicit component | `.bind().bind().execute().await?` pattern is too common to nest as `<MethodCall>` trees |
| Start in @shared, not @alloy-js/core | Faster iteration, can upstream later |
| `<If>` takes condition as string | Composed conditions are rare, string is simpler for 95% case |

## Open questions

- Should `@shared/statements` and `@shared/expressions` be one package or two?
  Single package is simpler, separate allows finer dependency control.
- Should the Go emitter migration happen alongside or after Rust proves the pattern?
- How to handle `<ElseIf>` / `<Else>` chaining -- sibling adjacency detection or
  `<IfChain>` wrapper component?

# Appendix A: Alloy Core Rendering Primitives (research)

## JSX primitives from @alloy-js/core

**Components:**
- `Block` -- indented code block, configurable opener/closer (default `{}`)
- `For` -- iterator over arrays/Maps/Sets, renders callback per item
- `List` -- static list with configurable joiners (hardline, comma, etc)
- `Declaration` -- creates symbol in scope, exposes via DeclarationContext
- `Scope` -- creates lexical scope for symbol binding
- `Name` -- renders the name from DeclarationContext (inside `<Declaration>`)
- `Show` -- conditional rendering (when/fallback props)
- `Output` -- root component; establishes binder, name policy, format options
- `SourceFile` / `SourceDirectory` -- file/directory structure

## Rendering pipeline

```
Output creates BinderContext + NamePolicyContext
  → render() executes component tree
  → accumulates file/directory entries
  → prettier AST nodes handle formatting
  → returns tree of { kind, path, contents } objects
```

## Children type
```typescript
type Child = RenderableObject | string | number | boolean | undefined | null
  | (() => Children) | Ref | Refkey | CustomContext | IntrinsicElement;
type Children = Child | Children[];
```

Raw strings pass through the prettier formatter unchanged. String children
are the primary escape hatch for emitting literal code.

## Intrinsic formatting elements (prettier-based)
- `<hbr />` -- hard line break (always breaks)
- `<sbr />` -- soft line break (breaks if line too long, else nothing)
- `<indent>` / `<dedent>` -- increase/decrease indent level
- `<group>` -- attempt single line; force breaks if hard break or width exceeded
- `<fill>` -- like group but only breaks before words exceeding width
- `<lineSuffix>` / `<ifBreak>` -- advanced conditional formatting

## Block auto-indent
```tsx
<Block>{children}</Block>
// Wraps in { } with auto hardline + indent around content
```

## For/List joining
```tsx
<For each={items} joiner=", " ender=";">
  {(item) => <>{item}</>}
</For>
// Supports: joiner, ender, comma, semicolon, line, softline,
// hardline, doubleHardline, space, literalline, skipFalsy

<List hardline comma enderPunctuation>
  <Item1 /><Item2 />
</List>
```

# Appendix B: Dialect Implementations (research)

## Rust dialect

```typescript
function createRustDialect(contextVis?: string): LangContext {
  return {
    language: "rust",
    syntax: {
      structKeyword: "struct",
      enumKeyword: "enum",
      functionKeyword: "fn",
      visibilityKeyword: (pub) => pub ? "pub" : null,
      referenceOp: "&",
      optionOp: (inner) => `Option<${inner}>`,
      errorReturnPattern: (retType) => `Result<${retType}, Error>`,
      awaitSyntax: "suffix",
      trySyntax: "suffix",
      formatCall: (tmpl, args) => `format!("${tmpl}", ${args.join(", ")})`,
    },
    declModifiers: {
      visibility: (pubProp) => {
        if (pubProp === true) return "pub ";
        if (pubProp === false) return "";
        return contextVis ? contextVis + " " : "";
      },
      mutability: (mutProp) => mutProp ? "mut " : "",
    },
  };
}
```

## Go dialect

```typescript
function createGoDialect(): LangContext {
  return {
    language: "go",
    syntax: {
      structKeyword: "type",        // "type Name struct { ... }"
      enumKeyword: "const",         // iota pattern, no keyword
      functionKeyword: "func",
      visibilityKeyword: () => null, // Case-based, not keyword-based
      referenceOp: "*",
      optionOp: (inner) => `*${inner}`,  // Pointer-based optionality
      errorReturnPattern: (retType) => `(${retType}, error)`,
      awaitSyntax: "none",
      trySyntax: "statement",
      formatCall: (tmpl, args) => {
        const goTmpl = tmpl.replace(/{}/g, "%s").replace(/{:.*?}/g, "%v");
        return `fmt.Sprintf("${goTmpl}", ${args.join(", ")})`;
      },
    },
    declModifiers: {
      visibility: () => "",          // Handled by NamePolicy case rules
      mutability: () => "",          // No concept in Go declarations
    },
  };
}
```

## TypeScript dialect

```typescript
function createTSDialect(): LangContext {
  return {
    language: "typescript",
    syntax: {
      structKeyword: "interface",
      enumKeyword: "enum",
      functionKeyword: "",
      visibilityKeyword: (pub) => pub ? "export" : null,
      referenceOp: "",
      optionOp: (inner) => `${inner} | null`,
      errorReturnPattern: (retType) => `Promise<${retType}>`,
      awaitSyntax: "prefix",
      trySyntax: "none",             // try/catch is block-level, not expression
      formatCall: (tmpl, _args) => `\`${tmpl}\``,  // Template literals
    },
    declModifiers: {
      visibility: (pubProp) => {
        if (pubProp === true) return "export ";
        if (pubProp === false) return "private ";
        return "";
      },
      mutability: () => "",
    },
  };
}
```

## Context provider component

```tsx
function LangContextProvider(props: { language: SupportedLanguage; children: Children }) {
  const dialect = createDialect(props.language);
  return (
    <LangContextValue.Provider value={dialect}>
      {props.children}
    </LangContextValue.Provider>
  );
}
```

## Relationship to NamePolicy

NamePolicy and LangContext are complementary:
- **NamePolicy** (existing, per-language): transforms identifiers
  - `myFunction` -> snake_case (Rust), camelCase (TS), PascalCase (Go exported)
  - Used during symbol creation
- **LangContext** (new): controls syntax around those identifiers
  - visibility keywords, type operators, error patterns, async placement
  - Used during JSX rendering

# Appendix C: Statement Component Full Specs (research)

## Let -- all edge cases

```typescript
interface LetProps {
  name: string;
  type?: Children;
  value?: Children;
  mutable?: boolean;
}
```

**Destructuring**: pass pattern string directly (`"{ name, age }"`, `"(a, b)"`).
The component doesn't parse it -- treats as opaque LHS.

**No value**: Rust allows `let x: i32;` (uninitialized). Go requires value for `:=`.
TS requires value for `const`. Component omits `= value` when undefined.

**Mutable flag**:
- Rust: `let mut x = 5;`
- Go: ignored (`:=` already implies mutable)
- TS: switches from `const` to `let`

## If/ElseIf/Else -- chaining design

Two options explored:

**Option A: Sibling adjacency** -- ElseIf/Else detect preceding If in JSX tree
```tsx
<If condition="x > 0">positive</If>
<ElseIf condition="x < 0">negative</ElseIf>
<Else>zero</Else>
```
Problem: JSX doesn't have sibling detection. Alloy renders children independently.

**Option B: IfChain wrapper** (recommended)
```tsx
<IfChain>
  <If condition="x > 0">positive</If>
  <ElseIf condition="x < 0">negative</ElseIf>
  <Else>zero</Else>
</IfChain>
```
IfChain collects children and joins with ` else `. Each If/ElseIf/Else renders
its own keyword + block. IfChain provides the glue.

**Option C: Single component with array prop**
```tsx
<If condition="x > 0" then="positive"
    elseIf={[{ condition: "x < 0", then: "negative" }]}
    else="zero" />
```
Compact but ugly for large bodies.

**Recommendation**: Option B. IfChain is minimal glue, bodies stay as children.

## ForIn -- iteration pattern differences

| Pattern | Rust | Go | TS |
|---------|------|----|----|
| value only | `for item in iter` | `for _, item := range iter` | `for (const item of iter)` |
| index + value | `for (i, item) in iter.enumerate()` | `for i, item := range iter` | `for (const [i, item] of iter.entries())` |
| index only | `for i in 0..len` | `for i := range iter` | `for (let i = 0; i < len; i++)` |
| while | `while cond { }` | `for cond { }` | `while (cond) { }` |

ForIn handles the first case (most common). Index iteration and while loops
need separate components or a `style` prop.

## Match/Arm -- semantic gap

Rust match is exhaustive and expression-level. Can assign result:
```rust
let x = match foo { A => 1, B => 2, _ => 0 };
```

Go/TS switch is statement-level with fallthrough. Different break semantics.

The component emits statement-level syntax for all targets. Expression-level
match-as-assignment needs a `<MatchExpr>` variant or wrapping in `<Let>`.

## Return -- Go multi-return

```tsx
// Single return (all langs)
<Return value="Ok(())" />

// Go multi-return
<Return values={["result", "nil"]} />
// Renders: return result, nil
```

Rust/TS ignore `values` prop, use `value` only.

# Appendix D: Expression Component Full Specs (research)

## Call -- namespace separator

```tsx
<Call namespace="sqlx" name="query" args={[sqlStr]} />
```
| Lang | Output |
|------|--------|
| Rust | `sqlx::query(sqlStr)` |
| Go   | `sqlx.Query(sqlStr)` |
| TS   | `sqlx.query(sqlStr)` |

Name casing comes from NamePolicy, not the Call component. Call just picks
`::` vs `.` based on language context.

## MethodCall -- async integration

```tsx
<MethodCall receiver="client" method="rest_call" args={["req"]} async />
```
| Lang | Output |
|------|--------|
| Rust | `client.rest_call(req).await` |
| Go   | `client.RestCall(req)` |
| TS   | `await client.restCall(req)` |

The `async` prop is sugar for wrapping in `<Await>`. Equivalent to:
```tsx
<Await><MethodCall receiver="client" method="rest_call" args={["req"]} /></Await>
```

## Try -- the hard problem

Rust `?` is postfix on any expression. Go error handling requires:
```go
result, err := SomeCall()
if err != nil {
    return err
}
```

This is fundamentally a different shape. Three approaches:

1. **Universal `<Try>` emits `?` for Rust, passthrough for others**
   Caller handles Go error checking separately. Simplest.

2. **`<GoTry>` emits the full if-err pattern**
   ```tsx
   <GoTry call={<Call name="SomeCall" />} result="result">
     {/* continue with result */}
   </GoTry>
   ```
   Renders: `result, err := SomeCall()\nif err != nil { return err }`

3. **Language-aware `<Try>` switches shape**
   For Rust: wraps expression with `?`
   For Go: splits into let + if-err
   For TS: wraps in try/catch

Recommendation: option 1 for now. Go emitter can use `<GoTry>` as a Go-specific
component built on top of the universal primitives.

## Chain -- composition vs nesting

Without Chain, a sqlx query looks like:
```tsx
<Try>
  <Await>
    <MethodCall receiver={
      <MethodCall receiver={
        <MethodCall receiver={
          <Call namespace="sqlx" name="query" args={[sql]} />
        } method="bind" args={["owner"]} />
      } method="bind" args={["name"]} />
    } method="execute" args={["conn"]} />
  </Await>
</Try>
```

With Chain:
```tsx
<Try><Await>
  <Chain
    start={<Call namespace="sqlx" name="query" args={[sql]} />}
    steps={[
      { kind: "method", name: "bind", args: ["owner"] },
      { kind: "method", name: "bind", args: ["name"] },
      { kind: "method", name: "execute", args: ["conn"] },
    ]}
  />
</Await></Try>
```

Chain is justified. The nested MethodCall version is unreadable.

## Fmt -- template syntax differences

```tsx
<Fmt template="/repos/{}/{}" args={["owner", "name"]} />
```
| Lang | Output |
|------|--------|
| Rust | `format!("/repos/{}/{}", owner, name)` |
| Go   | `fmt.Sprintf("/repos/%s/%s", owner, name)` |
| TS   | `` `/repos/${owner}/${name}` `` |

The `{}` placeholder syntax is Rust-native. For Go, the dialect's `formatCall`
converts `{}` to `%s`. For TS, the dialect inlines args into template literal
positions.

Named placeholders (`{owner}`) would require tracking arg names to positions.
Positional-only for v1.

# Appendix E: Migration Cost Analysis (research)

## By-the-numbers comparison

| Function | String lines | JSX lines (est) | Delta |
|----------|-------------|-----------------|-------|
| emitUpsertFn | 61 | ~55 | -10% (JSX wins slightly due to FunctionDecl + Chain) |
| emitExtractFn | 53 | ~50 | -6% |
| emitSyncTrait | 42 | ~30 | -29% (pure declarations, JSX natural fit) |
| emitSyncFn | 239 | ~200 | -16% |
| emitGraphqlFragment | 68 | ~65 | -4% (mostly string content) |
| emitConfigHelpers | 28 | ~25 | -11% |
| emitConfigCliMerge | 44 | ~40 | -9% |
| emitHttpRouter | 25 | ~22 | -12% |
| **Total** | **560** | **~487** | **-13%** |

Note: earlier subagent estimated JSX would be *larger*. That analysis assumed
wrapping every statement individually. With `<Chain>` collapsing bind sequences
and `<FunctionDeclaration>` handling signatures, JSX is actually competitive
or slightly smaller.

The real win is not line count but *structure visibility*. The JSX tree
makes the nesting structure of sync functions visible in the component tree
rather than hiding it in string indentation.

## Where JSX genuinely helps

1. **Function signatures** -- FunctionDeclaration handles params, returns, async, pub, attrs
2. **Method chains** -- Chain collapses `.bind().bind().execute().await?` into data
3. **Nested control flow** -- If/ForIn/Match make nesting explicit in JSX tree
4. **Cross-language portability** -- same JSX tree, different LangContext, different output

## Where string is still fine as children

1. SQL query text
2. JSON path access expressions
3. GraphQL field lists
4. Struct literal initialization (`SyncRequest { method: "GET", ... }`)
5. Simple expressions (`"Ok(())"`, `"true"`, `"0"`)

These are passed as string children to the JSX components. No ceremony needed.
