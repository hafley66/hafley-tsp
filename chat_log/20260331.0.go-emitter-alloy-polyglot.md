# Session: go-emitter-alloy-polyglot

## Goal
Add Go as a second language target alongside Rust, proving the FactDB abstraction is truly language-agnostic. Same TSP declarations, same fact extraction, different emitter output.

## Current State
- Go emitter built and working: 6_emit-go.tsx produces 614-line generated.go from same FactDB
- Uses @alloy-js/go@0.3.0-dev.3 (upgraded from 0.2.0 to fix alloy-core version conflict)
- Full pipeline: `npx tsp compile examples/ghcacher/_scaffold.tsp` outputs facts.json + schema.sql + generated.rs + generated.go
- 14 structs + 8 extraction structs + 14 upsert functions + 8 extract functions + JSON helpers in Go
- Alloy-go components used: ModuleDirectory, SourceDirectory, SourceFile, StructTypeDeclaration, StructMember (with tag prop for struct tags)

## Key Insights

### FactDB abstracts perfectly
Zero changes to TSP, zero changes to fact extraction, zero changes to SQL emitter. The Go emitter reads the same JSON the Rust emitter reads. Adding a new language target = one new file.

### Variance between Rust and Go emitters
- Struct emission: Go's StructMember tag prop (`db:"x" json:"x"`) came free. Rust needed custom #[derive] and #[serde] attr strings.
- Nullable: Rust Option<T> vs Go *T. One line in type mapper.
- SQL identical: same ON CONFLICT/RETURNING. Only placeholder syntax differs (? vs $N). Should be a SQL dialect fact, not baked per emitter.
- Package scope: Go needs ModuleDirectory + SourceDirectory wrapping. Rust uses CrateDirectory. Go's package system is more explicit in alloy.

### Alloy-go gotcha
@alloy-js/go SourceFile requires a package scope from parent ModuleDirectory + SourceDirectory. Without it: "A package is not in scope" crash. The test in alloy-go shows the pattern: ModuleDirectory("github.com/...") > SourceDirectory("pkg") > SourceFile("file.go").

### @alloy-js/go version pinning
@alloy-js/go@0.2.0 depends on @alloy-js/core@0.22.0 which conflicts with the rest of the workspace at 0.23.0-dev.12. Fix: use @alloy-js/go@0.3.0-dev.3 which accepts `>= 0.23.0-dev.12`.

### @Entity.default stringly-typed SQL
The `@Entity.default("(strftime(...))") ` pattern stores raw SQL strings. Should be replaced with intent-based decorators: @Entity.defaultNow, @Entity.defaultValue("main"), @Entity.defaultExpr("..."). The emitter translates intent to dialect-specific SQL.

### Earlier in session: route convention, vision convergence
- Finalized method resolution rules for query/mut namespaces
- File system convention: entity.tsp, routes.tsp, id_/ postfix underscore
- Explored sprefa + TSP + Prolog convergence architecture
- Three tiers of automation: manual, scaffold, full codegen
- Decorator soup accepted as input surface, with alternate binding model pattern available when soup gets too thick
- Relations: @belongsTo, @hasMany, @hasOne, @manyToMany on model properties
- Junction tables: @Entity.junction for composite PK
- Union strategy plugin: @Union.strategy for sum types in SQL
