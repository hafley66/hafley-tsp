## Problem/Context
User has validated TSP mechanisms (extern fn, namespace walking, fixed-point compilation, autozone injection) but the gap between "validated in fixtures" and "usable at work for codegen" is wide. ## Key Insights

### Method resolution (finalized)
- mut/create → POST, mut/update → PUT, mut/delete → DELETE, mut/updatePatch → PATCH
- mut/{anything_else} → POST (freeform action, name becomes path segment)
- query/read or query/get → GET, collapses to parent path
- query/{anything_else} → GET, name becomes path segment, @POST override for JSON body queries

### File system convention
- Folder name = path segment, snake_case always
- id_/ postfix underscore = param segment (Rust-safe, no brackets)
- entity.tsp = model + scalars at entity root
- routes.tsp = query/mut tree per path level
- side/, deps/ only at entity root, flow/ lives outside route tree
- Import DAG: _types.tsp ← entity.tsp ← routes.tsp ← _scaffold.tsp

### Three tiers of automation
- Tier 0: Manual (convention only)
- Tier 1: Scaffold (generate routes.tsp skeletons, user fills in ops between autozone markers)
- Tier 2: Full codegen (@crud decorator, fixed-point loop generates complete CRUD ops)

### Convergence architecture
- sprefa = comment-driven fact extraction across any language file
- TSP = authoring surface for domain types + extern fn mechanism
- Prolog = reconciliation engine, facts from sprefa + TSP + DB introspection, rules determine what each layer needs
- autozone = AST-scoped codegen injection (user wants tree-scoped, nestable, inline comment summoning)
- Mercury insight: type system intermediate as Prolog facts (sum types, product types, generics), per-target rules as emitters

### Relations / ORM collapse
- One model, many views: DB layer sees FK columns, API sees nested objects, create request drops auto fields
- Decorators on properties (@belongsTo, @hasMany, @manyToMany) indicate relation kind
- Prolog visibility rules per layer replace combinatorial JS emitter functions
- "Minimum output types" = distinct property-set combinations actually referenced by ops

### User's additional wants
- Dip in/out of autozone inline with comments, AST-tree-scoped markers, nested auto/manual zones
- Cross-language type sharing (Rust enums ↔ TS discriminated unions ↔ Kotlin sealed classes)
- Temporal/reactive constraints (rxjs-like scan/share/BehaviorSubject patterns as config)
- DB-external variables represented in type system
- sprefa match_links table already doing cross-file unification = same operation as Prolog unification
