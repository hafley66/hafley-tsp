# Session: gutfactdb-writeoutput-sync-analysis

## Goal
Continue pipeline compression: eliminate FactDB intermediate representation, wire alloy writeOutput, and analyze ghcacher for next generation targets.

## Current State
Committed cd3ac1f. Pipeline total 1,604 lines (was 2,900 pre-refactor). Two commits this session:
1. writeOutput from @alloy-js/core replaces manual render() → findFileContent() → writeFile()
2. FactDB gutted: 693 → 161 lines in 2_facts.ts. extractFacts() and all 21 flat table types deleted.

Emitters return OutputDirectory trees. $onValidate calls writeOutput(rustOutput, outputDir) and writeOutput(goOutput, outputDir). facts.json no longer emitted.

## Problem/Context
FactDB was dead code after emitters moved to walking Program directly (prior session). extractFacts() serialized the program graph into 21 flat tables, no consumer remained. writeOutput existed in @alloy-js/core but emitters were using manual findFileContent helpers to extract single files from rendered trees.

## Solution/Approach
- Emitters return `render(tree)` as OutputDirectory directly
- $onValidate uses writeOutput(output, basePath) from @alloy-js/core
- CrateDirectory and ModuleDirectory both default to path="." so output stays flat in tsp-output/
- Go SourceDirectory changed from path="db" to path="." with explicit name="db" for package name
- Summary stats in $onValidate computed from program graph (model.properties.size, relMap, etc.)

## Key Insights
- ghcacher sync functions (1,200 LOC across 4 files) are the highest-gain generation target
- The sync pattern is NOT GitHub-specific: endpoint + transport + freshness + strategy + nesting
- 5 knobs fully parameterize the sync skeleton: transport, endpoint, paginated, freshness, strategy + nesting
- All 5 knobs already have TSP decorators except freshness
- writeOutput from @alloy-js/core handles directory creation, file writing, overwrite logging
- Both CrateDirectory and ModuleDirectory default path="." (output lands directly in basePath)
- Go SourceDirectory derives package name from directory basename; path="." falls back to module name
- User explicitly identified async in-process sagas as future direction, eventually AsyncAPI
