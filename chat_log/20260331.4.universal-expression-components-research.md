# Session: universal-expression-components-research

## Goal
Design universal expression-level JSX components (Let, If, For, Call, Await, Try, Chain, etc.) that render valid imperative code in Rust, Go, and TypeScript from a single component tree. Eliminate string concatenation from the Rust emitter entirely.

## Current State
Full design doc written to chat_log/20260331.3.universal-expression-components-design.md (889 lines). Plan file at ~/.claude/plans/parallel-dazzling-iverson.md has the same content. No implementation started. User will read the design and decide whether to proceed.

## Problem/Context
The Rust emitter (5_emit-rust.tsx, 907 lines) uses JSX for declarations (structs, enums, traits) but string concatenation for function bodies (upserts, extractors, sync pipelines). The goal is to build Layer 1 (universal expressions) between the existing Layer 0 (declarations via Alloy) and a future Layer 2 (domain components like SqlQuery, SyncLoop).

Existing Alloy components cover: StructDeclaration, FunctionDeclaration, TraitDeclaration, EnumDeclaration, ImplBlock. Missing: Let, If, ForIn, Match, Return, Assign, Call, MethodCall, Await, Try, Field, Fmt, Chain.

## Solution/Approach
Three new packages:
1. @shared/lang-context -- LangContext interface with LanguageSyntax + DeclModifierProvider, dialect implementations per language (Rust/Go/TS), context provider component
2. @shared/statements -- Let, If/ElseIf/Else, ForIn, Match/Arm, Return, Assign
3. @shared/expressions -- Call, MethodCall, Await, Try, Field, Fmt, Chain

Key design: Option C dialect registry via Alloy's createContext pattern. Components call useLangContext() to get language-specific rendering callbacks. SQL/JSON/GraphQL content stays as string children.

## Key Insights
- Nobody has built reusable expression-level codegen primitives as a library. Haxe/Nim commit to being whole languages. JSII/Protobuf only do declarations. MPS is flexible but manual per backend. The expression layer is genuinely unexplored territory.
- Try/error-propagation is the hardest translation: Rust ? is expression-level, Go if err != nil is statement-level, TS try/catch is block-level. Universal Try only works for Rust/TS; Go needs GoTry as a separate component.
- Chain component is justified -- nested MethodCall for sqlx .bind().bind().execute().await? is unreadable without it.
- IfChain wrapper recommended over sibling adjacency (JSX has no sibling detection) or single-component-with-array-prop (ugly for large bodies).
- Migration cost: 560 string lines -> ~487 JSX lines (-13%). Real win is structure visibility, not line count.
- User's framing: "codify intent then reverse figure it out" -- the expression components ARE the intent codification; the dialect system is the "reverse figuring out" per target language.
