# Session: source-sync-rust-emitter

## Goal
Expand binding-core from SQL-only emission to full pipeline codegen: Source/Sync decorators, Rust emitter (structs, upserts, JSON extractors, GraphQL fragments, sync skeletons), with the understanding that TSP is a polyglot type system where CLI/HTTP/config/output are all just more type domains with different emitter targets.

## Current State
- Added Source namespace (5 decorators): @Source.graphql, @Source.rest, @Source.paginated, @Source.nested, @Source.pollInterval
- Added Sync namespace (1 decorator): @Sync.strategy("upsert" | "insert-ignore" | "delete-replace")
- Extended FactDB with 4 new fact tables: sources, source_nested, sync_strategies, source_fields
- Built 5_emit-rust.ts: produces 1143-line generated.rs from ghcacher TSP declarations
- ghcacher TSP files annotated with transport/strategy metadata
- Compiles and runs end-to-end: 14 entities, 8 sources, outputs facts.json + schema.sql + generated.rs
- NOT YET COMMITTED

## Key Insights
- The 84% "not generatable" number from last session was wrong. CLI args, HTTP client types, config structs, output formatting are all type declarations with behavior metadata. True manual zone is ~10%: git checkout orchestration and custom business logic hooks (state enum mapping, URL parsing, SHA-to-PR lookup).
- Alloy-rs autozone pattern (ReplaceFile/AutoZone/ManualZone) is how manual hooks survive re-emission.
- Every "domain" (Entity, CLI, HTTP, Config) follows the same pattern: TSP namespace with decorators → facts → emitter → target code with appropriate derives/attributes.
