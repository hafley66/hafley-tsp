# Session: scaffold-routes-namespace-design

## Goal
Design and validate the filesystem scaffolding system for hafley-tsp: routes.tsp namespace tree → generated directories + impl.tsp files with autozones, CRUD convention matching, and typed route params accessible in op signatures.

## Key Design Decisions

### Route info is namespace-based, not model-based
Models only support one level of member access in TSP. Namespaces support unlimited depth. Scaffolder generates:
```tsp
namespace Routes {
  namespace `todos/{id}` {
    alias template = "/todos/{id}";
    alias method = "GET";
    namespace params {
      alias id = string;
    }
  }
}
```

### Two modes for declaring paths
1. Shotgun: top-level routes.tsp declares whole tree, scaffolder generates all dirs + impl.tsp
2. Inline: nested routes.tsp per directory extends tree locally, top-level autozone auto-imports them

### lib/ns.tsp decorator set
```tsp
namespace ns;
extern dec param(target: Reflection.Namespace, typeName: valueof string);
extern dec autocrud(target: Reflection.Namespace);
extern dec mutations(target: Reflection.Namespace);
extern dec queries(target: Reflection.Namespace);
extern fn flattenRoutes(ns: Reflection.Namespace): unknown;
```

### impl.tsp anatomy (one per directory)
- AUTOZONE (regenerated): namespace, imports, route references
- Manual zone (one-time scaffold, dev owns): models, input stubs, mut/query namespaces with ops

### @mutations/@queries resolve POST ambiguity
Every op is mut or ref. HTTP method usually tells you, but POST is ambiguous (create=mut, query=ref). The containing namespace resolves it. @mutations children default POST, @queries children default GET. Override per-op with @put/@patch/@delete/@post.

### Convention matching (op name → HTTP method)
create → POST at own level, read/get*/fetch* → GET at own level, update → PUT, updatePatch → PATCH, delete → DELETE, query → POST + appends /query, anything else → POST + appends /name

### @autocrud generates full CRUD scaffold
On routes.tsp namespace: stamps impl.tsp with model stubs + all standard CRUD ops. Remove @autocrud to go manual. Eject path is clean.

### flattenRoutes stays as TSP fn for scaffolder internals
The fn works correctly at runtime (creates models, logs route tables). It just can't project results into TSP's static type system. The scaffolder CLI runs it in JS and writes the results as static namespace declarations.

## TSP Limitations Discovered
1. fn-created model properties invisible to static member access (unknown, Reflection.Model, spread all fail)
2. Model member access limited to one level (A.b works, A.b.c doesn't, alias chaining doesn't bypass)
3. Spread from unknown/fn-result is syntactically valid but copies nothing
4. $ not valid in TSP identifiers
5. No backtick identifiers for namespaces (but backtick works for model property NAMES and namespace NAMES)
