## Problem/Context
TypeSpec decorator authoring requires 4 files touched per decorator (tsp declaration, ts implementation, state key, getter). The factory reduces TS boilerplate, and @decoratorDef lets you define decorators as TypeSpec models, but the larger design question is how decorators drive emitter output.

## Solution/Approach
- TypeSpec as type algebra, not OpenAPI frontend. Emitters are projections.
- min(type): one model, @visibility controls field subsets per layer (api, db, create). Decorators carry mapping metadata (@column, @jsonName) so types stay singular.
- Scan-based emitter (rxjs scan semantics): prev file state + current TypeSpec program = delta. AST-grep pattern matching over string sigil zones.
- .tsp file path maps directly to output directory structure (no namespace-to-directory convention)
- Parameterized route segments use trailing underscore: user_id_/
- Each route level gets predictable files: mod.rs, models.rs, http.rs
- Auto zones in same file (not separate _auto.rs files)

## Key Insights
- Decorators run as encountered during compilation, not after. State is fully populated by $onEmit time.
- The 80% decorator case: attach a value to a node. flagDec/valueDec/objectDec/listDec/exclusiveDec covers it.
- Visibility projections: same name + same type + different audience = visibility. Different name or type = different type, no casting.
- Namespaces as app boundaries -- cross-namespace refs = cross-boundary deps, emitter generates transport.
- .tsp source file path should directly map to emitter output directory (no invented convention).
- Reactive sentinel idea for declarative emitters: JS values as cursors into TypeSpec semantic graph, not string paths. Deferred for later.

## Open Questions
- How to declare emitter behavior as part of decorator definition (per-instance vs aggregate vs modifier)?
- Prolog-like reactive sentinels for declarative emitter rules -- deferred but interesting
- Can we generate validation bodies from decorator model property shapes?
- Curried decorators -- TypeSpec functions can't return namespaces, workarounds exist but clunky
