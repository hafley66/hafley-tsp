# Session: polyglot-intent-compiler-design

## Goal
Design the conceptual architecture for using TypeSpec as a polyglot intent compiler -- declaring patterns/semantics once in TSP and emitting to any language, transport, broker, or tool.

## Current State
Pure design/brainstorming session. No code written. Produced a comprehensive taxonomy of axes, primitives, and composition patterns. Identified TSP language gaps (variadic generics, deep path access, constraint validation). Ready for a follow-up session to produce a tight spec document.

## Problem/Context
The emit-helper package (previous session) handles type structure emission, but the real scaling problem is: how do you declare arbitrary intent (CLI calls, reactive streams, coroutine protocols, DAG workflows, boundary protocols) once in TSP and emit it to N languages × M transports without N*M manual emitter code?

## Key Design Artifacts

### 1. Template String as Source of Truth (not models)
Routes, channels, CLI commands are all template strings with positional slots:
```
cli:    program subcommand --flag value  pos1 pos2
http:   POST    /subcommand ?flag=value  {body}
ws:     {"op": "subcommand", "flag": "value", "pos": [...]}
grpc:   Service.Subcommand(SubcommandRequest { flag, pos })
```
TSP model carries the kwargs, template string carries the positional args (*args). Emitter serializes to target's delimiter/encoding convention. Route/channel/CLI are all the same primitive -- a template string + typed args.

### 2. Companion Model Pattern ("matches")
Instead of decorator soup on every property, use typed overlays:
```typespec
model A { b: string; c: number; }
model AA matches A {
  b: SomeSpec<A.b>;
  c: SomeSpecOther<A.c>;
}
```
Compiler-enforced exhaustiveness, each wrapper carries a ref to source field. Multiple overlays per concern (validation, proto field numbers, serialization). TSP doesn't have this yet -- proposed language feature.

### 3. Coroutine Protocol as Universal Contract
Generator<Yield, Return, Next> shape describes cross-language coroutine interop:
```typespec
@coroutine
model PriceFeed {
  yield: PriceUpdate;
  next: Subscription;
  return: FinalSummary;
}
```
Each language emits its native coroutine machinery. The boundary between languages is a transport (gRPC bidi, WebSocket, shared memory ring buffer, Unix socket). Transport is an emitter facet.

### 4. Shared Memory / Sidecar as Emitter Target
Same coroutine protocol, transport varies by deployment:
- Shared memory (ring buffer): ns latency, same machine, zero-copy
- Unix socket: us latency, sidecar
- TCP/gRPC: ms latency, cross-host
Shared memory facet adds @packed @align(8) constraints that other facets ignore.

### 5. Complete Axis Taxonomy

#### 5a. Temporal Shape (messages per exchange) -- 6 patterns
```
@call           // 1 in, 1 out (request/response)
@fire_forget    // 1 in, 0 out (no ack)
@stream         // 1 in, many out (SSE, subscription)
@sink           // many in, 1 out (upload, batch collect)
@drain          // many in, 0 out (log sink, UDP firehose)
@bidi_stream    // many in, many out (WebSocket, gRPC bidi)
```

#### 5b. Spatial Shape (peer topology) -- 4 patterns
```
@unicast        // 1 peer (default)
@broadcast      // 1->M peers (fanout)
@merge          // M->1 peers (funnel)
@mesh           // M<->M peers (p2p)
```

#### 5c. Universal Axes -- 5
| Axis | Values |
|---|---|
| Temporality | sync, async |
| Direction | read, write, readwrite |
| Nullability | required, optional |
| Fallibility | infallible, fallible(E) |
| Temperature | hot, cold |

#### 5d. Rust-specific Axes -- 4 (collapse to defaults in GC langs)
| Axis | Values | GC default |
|---|---|---|
| Ownership | owned, ref, mut | owned |
| Lifetime | static, scoped | static |
| Sizing | sized, unsized | sized |
| Thread safety | send, sync, local | send+sync |

#### 5e. Protocol Axes -- 4
| Axis | Values |
|---|---|
| Consumption | once, reusable |
| Backpressure | bounded(n), unbounded |
| Cancellation | cooperative, forced, none |
| Ordering | ordered, unordered |

#### 5f. Reactivity Facet -- 3 sub-axes
Overflow strategy: @overflow_buffer (concatMap), @overflow_drop_old (switchMap), @overflow_drop_new (exhaustMap), @overflow_concurrent (mergeMap)

Merge combination: @merge_interleave (merge), @merge_combine_latest, @merge_zip, @merge_race, @merge_fork_join

Replay: @replay_last (BehaviorSubject/StateFlow/watch), @replay_all (compacted topic)

#### 5g. Messaging Facet -- 1 sub-axis
Delivery: @at_most_once (QoS 0), @at_least_once (QoS 1), @exactly_once (QoS 2)

### 6. Pipe Composition (North Star)
RxJS pipe as the universal composition primitive:
```typespec
model MediaPipeline is Pipe<
  ReceiveUpload,
  Retry<StoreToS3, {max: 3}>,
  Buffer<EnqueueTranscode, {size: 100}>,
  Fan<UpdateCatalog, NotifyUser, InvalidateCDN>
>;
```
Maps to: Rust async fn chain, Go errgroup, Airflow DAG, Temporal workflow, Celery Canvas, RxJS pipe.

TSP limitation: no variadic generics, so must flatten to Pipe2<A,B>, Pipe3<A,B,C> etc. Keyword generic instantiation helps readability. Constraint validation (output of step N = input of step N+1) may need compiler plugin.

### 7. Postgres Ecosystem Analogy
PostgREST/PostGraphQL pattern: one schema, many mechanical projections. TSP is the schema, emitters are the projections. But emitters are ~50-100 lines of TargetLang facet implementation, not separate binaries.

### 8. Airflow Strangler Pattern
Emit Airflow DAGs from TSP today (drop-in replacement), simultaneously emit Rust binary from same TSP, swap nodes incrementally from Python to Rust, eventually replace Airflow entirely.

### 9. CLI-to-Daemon Bridge
Emit CLI parser and HTTP server from same model -- guaranteed to match. Space delimiter (CLI) = path delimiter (HTTP) = JSON key (WS). Same intent, different serialization. Can optionally support same interface via WebSocket or SSE.

- `matches` keyword for companion models -- proposed feature for TSP team
- How far can TSP templates go before needing compiler extensions?
- Should the emitter be a router to existing codegen tools (protoc, OpenAPI generators) rather than owning all output?

## Key Insights
- Route/channel/CLI are all the same primitive: template string + typed args, different serialization per target
- Every async app is some shittier version of rxjs pipe -- the north star is emitting rxjs-grade composition to any language
- Models are the most expressive unit in TSP (more than operations) -- model everything with models
- Decorator soup on properties doesn't scale -- companion "matches" models are the solution
- M->M patterns always decompose into M->1->1->M (hub) -- 5 genuinely distinct patterns not 8
- Temporal (messages per exchange) and spatial (peers per channel) are orthogonal cardinality axes
- The GTOR matrix (singular/plural x spatial/temporal) plus Rust's ownership axis covers the reactivity design space
- Emitters can be routers to existing tools (protoc, etc.) -- don't have to own all codegen
- Airflow/Temporal/Celery Canvas are all shitty pipes -- same primitives, different serialization
- TSP keyword generic instantiation is a major advantage over TypeScript for readability
