# Session: sync-emitter-syncclient-trait

## Goal
Complete the sync function emitter in binding-core's Rust emitter. Close the gap between
data-layer generation (structs, upserts, extractors) and orchestration-layer generation
(sync functions that poll APIs and persist to SQLite).

## Current State
Committed (4d5404f). 907-line emitter produces 1,453-line generated.rs with 8 sync
functions, SyncClient trait, GraphQL field constants with nested sub-selections.

## What Was Built
- @Source.freshness("etag"|"last-modified"|"poll-only") decorator
- @Source.nested wired in ghcacher .tsp source models
- SyncClient trait + SyncPollState/SyncRequest/SyncResponse emitted types
- emitSyncFn rewritten: generic path params, freshness-aware requests, poll state
  persistence, nested child sync inline, array index path handling
- emitGraphqlFragment enhanced with @Source.nested sub-selections
- getAllSourceNested accessor added to decorators.ts

## Key Design Decisions
- SyncClient trait for transport generality (level 1 seam points)
- SyncPollState (not PollState) to avoid collision with user entity of same name
- Path params extracted generically from {param} in REST templates, not hardcoded
- Nested children synced inline after parent upsert, matching ghcacher pattern
- GraphQL FIELDS constants auto-include nested sub-query blocks

## Remaining Gaps
- Anonymous model sub-fields in GQL queries (requestedReviewer { login name })
- pr_label / pr_requested_reviewer: junction tables without @Bind.from, not nested yet
- Go sync emitter (step 6 of plan)
- Level 2 composability (pluggable emitter phases) deferred
