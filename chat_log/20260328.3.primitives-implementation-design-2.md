# Session: primitives-implementation-design-2 (continued)

## Goal
Continued design of polyglot intent compiler primitives. Shifted from decorator-heavy approach toward namespace-convention-driven architecture with TSP functions as compile-time inference engines.

## Current State
Major architectural breakthroughs:
- Namespace tree IS the metadata (no decorators needed for CRUD categorization)
- Mutation ops ARE events (no separate union declaration needed)
- Op type signatures form a dependency DAG (prolog-style inference)
- TSP 1.10 functions can receive full namespace reflection and synthesize types at compile time
- Verified: namespace nesting, function namespace passing, alias indirection for computed types all compile

## Key Discoveries

### 1. Namespace-as-Convention (replaces most decorators)
```
Entity/
  model             the noun, typed FK refs = relations
  query/            pure reads, auto-streamable
    op get
    op list
  mut/              state changes (ops ARE events)
    create/         constructors
    update/         modifiers
    delete/         destructors
  side/             impure effects, @after linked
  deps/             cross-boundary references
  flow/             orchestration (DAG-resolved)
  domain/           pure business rules (optional, add when complex)
```

### 2. Mutations ARE Events
No separate union Event declaration. The emitter walks mut.** and derives:
- Event union from op names
- Reducer match arms from op signatures
- REST endpoints from namespace path
- Event store schema from op params

### 3. Prolog-Style DAG Resolution from Type Signatures
Op signatures encode dependency graph through their types:
```
createOrder(Cart) → Order
checkStock(Order) → StockResult        // needs Order → after createOrder
validateAddress(Order) → AddressResult  // needs Order → parallel with checkStock
charge(Order, Reservation) → Payment   // needs both → after reserve
```
Emitter topologically sorts, infers Sequence/Parallel/Choice/Loop automatically.
Types are logic clauses. Emitter is the solver.

### 4. TSP Functions as Compile-Time Inference Engine
Verified experimentally:
- Functions take Reflection.Namespace, access .models, .operations, .namespaces
- Functions take Reflection.Model, access .properties
- Functions return Reflection.Model, usable via alias indirection
- alias + is/spread/op params all work with function-computed types
- Full namespace tree walkable from JS at compile time

Key functions to build:
- mutationEvents(ns) → synthesized Union from mut.** ops
- flowGraph(ns) → dependency edges from type analysis
- propType(model, path) → deep property access workaround

### 5. I/O Channels Simplified
Two channels: I (input) and O (output).
Errors are tagged subset of O, not a separate channel.
@err decorator on model fields marks error-path O variants.
No @err = target's default error handling (panic, 500, anyhow).
intent.fallible dropped from taxonomy.

### 6. query vs mutation (replaces read/write/readwrite)
- query: pure read, cacheable, auto-streamable, retryable
- mutation: side effect, state change
- All queries auto-streamable (React Query = polling subscription = same thing)
- Subscriptions are queries that stay open (temporal decorators determine how long)

### 7. Relations = Cross-Namespace Type References
No join decorators needed. Type references across namespaces ARE relations:
- `customer: Customers.Customer` = FK
- `items: Item[]` = has-many
- Views = query ops returning multi-entity types
- Emitter infers JOINs from cross-namespace type dependencies

### 8. Progressive Side Effect Extraction
namespace side/ with @after links to mutations.
@opaque marks "exists but not yet untangled" for brownfield.
Strangler pattern: @opaque blob shrinks as effects are extracted.

### 9. Resolution Engines
Namespace name or decorator signals which engine processes the ops:
- flow → DAG solver (topological sort by type deps)
- mut → event sourcing (reducer arms by lifecycle)
- query → projection (auto-streamable reads)
- deps → boundary linker (cross-namespace, emitter picks transport)
- side → effect chain (@after edges)

### 10. Deployment-Independent Boundaries
Namespace = bounded context, not service. Deployment config maps namespaces to services:
- Same service → direct function call
- Different service → emitter generates HTTP/gRPC client
TSP doesn't change between monolith and microservices.

### 11. Scope as Decorator (simplified from earlier)
Dropped the Scope base model/marker idea - too verbose for the gain.
Still an open question for expressing in-process vs durable stream lifecycles:
- scope.local: in-memory, dies with process
- scope.durable: broker-backed, survives restarts

### 12. Composition Operators (4 irreducible)
Sequence, Parallel, Choice, Loop as model templates.
Compile in TSP as nested generics: Sequence<A, Sequence<B, C>>.
BUT: type signatures already encode this implicitly (prolog inference).
The explicit operators exist as emitter intermediate representation, not user-authored.

### 13. Revised Primitive Taxonomy (39 → streamlined)

Dropped from taxonomy:
- intent.read/write/readwrite → replaced by query/mut namespace convention
- intent.fallible → replaced by @err fields on models
- intent.optional → stays (I/O channel nullability)
- Rust namespace (9) → removed, lang-specific is emitter concern

Namespace convention replaces decorators:
- query/* → was intent.read
- mut/* → was intent.write
- mut.create/update/delete → was separate lifecycle decorators

Remaining decorator primitives:
- temporal(6): call, fire, stream, sink, drain, bidi
- spatial(4): unicast, broadcast, merge, mesh
- rx(13): async, hot, replay_last/all, overflow(4), merge/latest/zip/race/join
- intent(2): optional, idempotent
- delivery(5): at_most_once/at_least_once/exactly_once, ordered, unordered
- lifecycle(5): once, reusable, cancel.cooperative/forced/none

Total decorators: ~35 (down from 48)
Namespace conventions replace ~13 decorators

## Verified TSP Experiments
1. Nested namespaces with ops: ✅ compiles (TSP 1.10)
2. A.b single-level property access: ✅ works, resolves to property type
3. A.b.c multi-level chaining: ❌ "cannot resolve in ModelProperty"
4. Model templates as composition operators (Sequence<A, B>): ✅ compiles
5. extern fn taking Reflection.Namespace: ✅ full tree access (models, ops, child namespaces)
6. extern fn returning Reflection.Model: ✅ usable via alias
7. alias + is/spread/op signatures with computed types: ✅ works through alias indirection
8. Direct function call in is/spread/op: ❌ must go through alias
