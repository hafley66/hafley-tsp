# Session: fixedpoint-codegen-minilang-validated

## Goal
Validate and build a fixed-point TSP compilation system where extern fns write static declarations back into source files during compile, enabling checked deep access on generated code.

## Current State
- Fixed-point compilation loop: VALIDATED AND WORKING
- In-file autozone injection: VALIDATED AND WORKING
- fn reads call site via ctx.functionCallTarget: VALIDATED
- Namespace-based deep access: VALIDATED (unlimited depth via ExportContainer resolution)
- Model-based deep access: HARD LIMIT at 1 level (ModelProperty lacks MemberContainer flag)
- Cursor scalar mini-lang (Ns model with NsPath/NsName/NsMethod scalars): VALIDATED, fn can read distinct scalar types through reflection
- File watcher script: written, untested in live workflow
- 18 validation fixtures (16 passing, fixture 10 is known fn-returns-fn limit)

## Key Findings

### fn return type limitations (architectural, confirmed via compiler source)
- Member access uses symbol tables (bind time). fn results exist at check time. Phase mismatch.
- name-resolver.ts line 415: resolveMemberExpressionForSym dispatches on MemberContainer vs ExportContainer flags
- types.ts line 1077: MemberContainer = Model | Enum | Union | Interface | Scalar (no Namespace)
- types.ts line 1073: ExportContainer = Namespace | SourceFile
- Model property access: one level only. ModelProperty nodes are leaves in the symbol tree.
- Namespace export access: unlimited depth. Each child namespace is itself an ExportContainer.
- fn returns: composable (alias, is, spread with model literal constraint, fn-to-fn chaining) but member access fails on unknown/Reflection.Model return constraints
- Model literal return constraints enable member access: `extern fn f(): { myProp: string }` works
- Functions cannot have template parameters (FunctionDeclarationStatementNode does not extend TemplateDeclarationNode)
- Template alias wrapper is the documented pattern: `alias Read<M extends Model> = applyVisibility(M, filter);`
- No type assertions/casting in TSP

### Fixed-point compilation mechanism
- fn has full Node.js access (fs, process)
- ctx.functionCallTarget gives CallExpressionNode with pos/end byte offsets
- Parent walk reaches source file path
- fn reads source file, finds AUTOZONE markers, replaces content between them
- Writes .tsp-dirty sentinel file if changes made
- Outer shell script loops until no dirty flag (converges in 2 passes deterministically)
- TSP namespace merging allows autozone to reopen existing namespaces

### Cursor scalar mini-lang (validated)
- Distinct scalars (NsPath, NsName, NsMethod) extending string
- Ns model groups them with type-checked dot access
- Pattern model uses Ns.path as property type, compiler resolves to NsPath scalar
- fn reads prop.type.type and sees Scalar with distinct name, can dispatch
- Backtick property names work for dynamic keys (`Ns.path` as key)
- Limitation: Ns.path works as property TYPE but fails as template ARGUMENT (ModelProperty not assignable to string)

### Community landscape
- Nobody in TSP community uses namespaces as structured data carriers
- Nobody uses backtick namespace names for path/route representation
- fn limitation discussions (#521, #7296) focus on extern type/extern template fn proposals
- The namespace-as-data-carrier pattern appears novel

## Explored But Parked
- Prolog engine embedding in codegen fn (Tau Prolog): mechanically feasible, binding goes wrong direction (extracts to JS instead of TSP declaring facts)
- Full mini-lang with opcode vocabulary (Literal/Collect/Recurse marker models): works but compression ratio worse than hardcoded JS for single use case
- TSP model as Prolog-like rule declaration: interesting but reimplements Prolog badly
