## Key Discoveries

### 1. Timing Semantics on Side Effects
Three timing decorators replace vague @after:
```
@before(op)    sync, pre-condition, blocks execution, same transaction
@after(op)     sync, post-condition, same transaction, rollback together
@on(op)        async, event emitted to bus, no transaction coupling
```
@on is the key one: "I listen for when this occurs" without specifying where/when.
Emitter instruments the mutation to emit an event. Listener is decoupled.
Cross-entity @on = bus subscription, event type derived from mutation return type.

### 2. Flow as Coroutine Instance
Flows have four models mapping to Generator<Yield, Return, Next>:
- Input: what starts the flow (external, provided once)
- Self: accumulator state (lives across yields, serializable)
- Yield: what the flow produces at each step (observable from runner)
- Next: what the flow receives to resume (injectable at @suspend points)

Emitter generates enum state machine in Rust (each variant = suspension point, Self serialized inside).
Self being serializable = durable execution for free (Temporal-style checkpointing).

But: flow model is sequential-biased. Real systems have concurrent interleaving flows.
Resolution: flow/ is one namespace convention among several, not the primary abstraction.
Entity-level mut→event→reduce→side loop is the general foundation.

### 3. Flow Is Just Ops Calling Ops
Flow ops aren't special. They call entity query/mut ops.
A flow IS just a query or mutation from the outside.
Flows call flows. Side effects start flows. No special runtime.
The flow/ namespace just means "apply DAG solver to figure out call order."

### 4. System Graph Traversal
One function walks all namespaces and collects all edges:
```typescript
interface Edge {
  from: string;
  to: string;
  kind: "before" | "after" | "on" | "requires" | "triggers" | "fk" | "flow_dep";
  timing: "sync" | "async";
  transaction: "same" | "independent";
}
```

Graph answers: what happens when X runs, what depends on Y, if service Z goes down what breaks, full lifecycle of an entity, all async boundaries (= bus topics).

Rendering: solid=sync, dashed=async, color=same tx vs independent, shape=entity/side/flow.

### 5. Brownfield Progressive Adoption via @impl
Flip direction: TSP describes existing code instead of generating it.
```typespec
@impl("src/routes/orders.ts", "submitOrder")
op submit(id: string): Order;

@impl("src/routes/orders.ts", "submitOrder", line = 47)
@opaque
op legacyWebhook(order: Order): void;
```

Progressive phases:
1. @impl everything, @opaque unknowns → system diagram, code unchanged
2. Replace some @impl with generated code → mixed ownership
3. @opaque blobs extracted into explicit ops → graph gets precise
4. All @impl gone → TSP owns everything, full codegen

@impl is verifiable: emitter checks file/function exists, signature matches.

### 6. DAG Ambiguity Resolution (from earlier turns)
When multiple ops produce same type:
1. Unique type match (only one producer → wire it)
2. Move semantics (T→T pass-through → linear chain, consumed once)
3. Parameter name hint (weak preference)
4. @from explicit wire (user override)
5. Error (ambiguous, report candidates)

External inputs: params whose types no op produces → flow's function signature.
Terminal outputs: op outputs nothing consumes → flow's return type.
Scalar newtypes (OrderId vs string) eliminate most ambiguity without decorators.

### 7. Self as Flow Accumulator
model Self in flow namespace = state bag threaded through every op.
Emitter wires it: each op output assigned to matching Self field.
Enables debugging (inspect between steps) and serialization (durable flows).
scope.local: Self in memory. scope.durable: Self persisted to store.

## Revised Namespace Convention

```
Entity/
  model              the noun, typed FK refs = relations
  query/             pure reads, auto-streamable
  mut/               state changes (ops ARE events)
    create/          constructors
    update/          modifiers
    delete/          destructors
  side/              impure effects with timing:
    @before(op)      sync pre-condition, same tx
    @after(op)       sync post-condition, same tx
    @on(op)          async, event bus, independent
    @opaque          unknown internals (brownfield)
  deps/              cross-boundary references
  flow/              orchestration (DAG-resolved from type signatures)
    model Input      external inputs
    model Self       accumulator state
    @suspend op      coroutine yield point
  domain/            pure business rules (optional)
```
