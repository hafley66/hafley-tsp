# Session: polyglot-intent-compiler-primitives

## Goal
Design the complete primitive taxonomy for using TypeSpec as a polyglot intent compiler -- declaring reactive/async/CRUD/streaming patterns once, emitting to any language, transport, or broker.

## Current State
Pure design session building on previous emit-helper work. Produced comprehensive 48-decorator taxonomy across 8 namespaces, 10 named common combos, event-sourcing/scan-based CRUD capability templates, and the union-variant-as-mutation-endpoint pattern. No code written. Ready for spec document and prototyping.

## Problem/Context
The emit-helper package handles type structure emission, but scaling to N languages x M transports x P protocols requires a well-defined set of orthogonal primitives that cover the full design space. Need to handle: CLI calls, reactive streams, coroutine protocols, DAG workflows, event-sourced CRUD, and boundary protocols -- all from the same TSP source.

## Solution/Approach

### Primitive Taxonomy (48 decorators, 8 namespaces)
- **Temporal** (6): call, fire_forget, stream, sink, drain, bidi_stream
- **Spatial** (4): unicast, broadcast, merge_peers, mesh
- **Flow** (8): async, hot, replay_last, replay_all, overflow_buffer/drop_old/drop_new/concurrent
- **Combine** (5): combine_interleave/latest/zip/race/join
- **Intent** (6): read, write, readwrite, optional, fallible, idempotent
- **Delivery** (5): at_most_once/least_once/exactly_once, ordered, unordered
- **Lifecycle** (5): once, reusable, cancel_cooperative/forced/none
- **Rust** (9): owned/ref/mut, static_life/scoped, unsized, send/sync/local

### Key Patterns
1. Template string first (routes/channels/CLI), model carries kwargs only
2. Union variant name = universal mutation discriminator (route segment, gRPC method, CLI subcommand, NATS subject leaf)
3. @state(EventUnion) on model = scan accumulator, derives reducer, event store, read model
4. Capability templates: Readable<T>, Writable<T,E>, Subscribable<T>, Crud<T,E>, LiveCrud<T,E>
5. Pipe<A, B, Fan<C, D, E>> as north star composition (blocked on TSP variadic generics)
6. Resolved facets + amendment functions for emitter scaling

### 10 Common Combos
HttpEndpoint, Subscription, EventPublish, WorkerQueue, RealtimeBidi, StateSync, ScatterGather, LiveQuery, PipelineStep, MetricsDrain

## Key Insights
- Route/channel/CLI are all template string + typed args, different serialization per target
- Every async app is a degraded version of rxjs pipe -- pipe composition is the universal primitive
- Models are the most expressive unit in TSP (more than operations)
- Temporal (messages per exchange) and spatial (peers per channel) are orthogonal cardinality axes -- previous enumeration conflated them
- "Bidi" means streams on both sides, not just two types (call has args+return but is not bidi)
- Hot pulls in 3-4 additional decorators automatically (cancel, replay, overflow)
- Spatial shape determines combine strategy; reliability vs latency determines delivery+overflow
- @state(EventUnion) is the key primitive for event sourcing -- one decorator derives reducer, store, read model, and REST/gRPC/GraphQL endpoints
- Union variant name is the universal discriminator across all transports
- M->M always decomposes to M->1->1->M -- 5 genuinely distinct temporal patterns
- Rust is the max-unambiguity target (forces explicitness on most axes), easier langs default away
- Airflow/Temporal/Celery Canvas are all shitty pipes with different syntax for concat/chord/group
- Postgres ecosystem (PostgREST/PostGraphQL) is the existence proof: one schema, many projections

## Open Questions
- How to achieve pipe input/output type threading in TSP? Variadic generics don't exist.
- Deep type pathing (A.b.c.d) -- needed for @derived cross-aggregate joins
- `matches` keyword for companion models -- avoids decorator soup
- Where clauses / type-level assertions for constraint validation
- Should overflow/combine/replay be on the model or on the Pipe step wrapping it?
- How does @derived cross-aggregate state interact with consistency boundaries?
- Can the common combos be TSP template aliases, or do they need special compiler support?
