## Key Technical Details

### Fact tables (2_facts.ts)
11 tables: entities, fields, pks, uniques, indexes, defaults, manuals, relations, bindings, field_maps, auto_maps. Extracted by walking all models in $onValidate, reading decorator state via accessor functions.

### SQL emitter (4_emit-sql.ts)
Consumes FactDB, produces CREATE TABLE + CREATE INDEX. FK resolution joins field + relation + target pk facts. Composite PK when pk count > 1. AUTOINCREMENT only on INTEGER single PKs. Dot-paths flattened with underscore.

### Junction pattern
@Rel.belongsTo @Entity.pk on same field = FK as part of composite PK. Optional row ID: use @Entity.pk id: integer + @Entity.unique instead.

### Coverage analysis vs real ghcacher
~16% of 5,422 lines of Rust are mechanical plumbing (schema, upsert functions, row structs, bind chains, test fixtures) derivable from facts.json. 84% is domain logic, orchestration, CLI.
